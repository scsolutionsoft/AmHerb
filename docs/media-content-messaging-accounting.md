# ภาพสินค้า ข่าว โฆษณา การสนทนา และบัญชีการขาย

## ภาพสินค้าและแบรนด์

- หลังบ้าน → สินค้า → แก้ไข → จัดการภาพสินค้า หรือ `/Media/Product/{ProductId}`
- ช่อง 1–4 เป็นแกลเลอรีหลัก ช่อง 5 เป็นภาพอธิบายข้อมูลสินค้า รองรับ JPEG, PNG, WebP ไม่เกิน 5 MB ต่อภาพ
- เก็บไฟล์จริงใน SQL Server `MediaAssets.Data` (varbinary(max)) พร้อมชนิดไฟล์และคำอธิบายภาพ ไม่มีไฟล์อัปโหลดใน wwwroot
- เปลี่ยนภาพเดิมได้ตามช่องและลบได้ ภาพหลักเลือกช่องที่มีเลขน้อยที่สุด ภาพย่อวงกลมใช้ใน POS สต๊อก ตะกร้า คำสั่งซื้อ และหลังบ้าน
- คลิกภาพเพื่อเปิด modal ขนาดใหญ่ รองรับปุ่มปิดและ Escape
- ภาพแบรนด์หน้าแรกและ Login ใช้ภาพแนบที่ 2, 3 และ 4 เดิม จัดภาพด้วย CSS โดยไม่ดัดแปลงบุคคลหรือใส่คำรับรองสรรพคุณ
- คำสั่งนำเข้าภาพแบรนด์สำหรับผู้ดูแลเครื่อง: `dotnet run --project src/AmHerb.Web --no-build --launch-profile http -- --import-brand "C:/Users/Oh-z600-A/OneDrive/GitHub/AmHerb/artifacts/import"` โดยโฟลเดอร์ต้องมี attached-2, attached-3, attached-4 พร้อมนามสกุลภาพ
- การสำรองฐานข้อมูลต้องรวมข้อมูลภาพด้วย ภาพสมาชิก/ฉบับร่างตรวจสิทธิ์และเวลาเผยแพร่ทุกครั้งที่อ่าน

## ข่าวและโฆษณา

- `/News` แสดงเฉพาะรายการที่เปิดเผยแพร่ อยู่ในช่วงเวลา และตรงกลุ่มผู้ชม
- Marketing/Admin/SuperAdmin จัดการได้ที่ `/News/Manage` แยกข่าวและโฆษณา เลือกบุคคลทั่วไปที่ยังไม่ล็อกอิน สมาชิกที่ล็อกอิน หรือทุกคน
- แบบฟอร์มรับวันเวลาไทยและบันทึกเป็น UTC โดยจุดสิ้นสุดไม่รวมอยู่ในช่วงเผยแพร่
- โฆษณาปรากฏทั้งหน้าแรกและหน้าสมาชิกตามสิทธิ์ เนื้อหาเป็นข้อความปลอดภัย ลิงก์ต้องอยู่ภายในเว็บไซต์
- การสร้างโฆษณาไม่ได้สร้างส่วนลดอัตโนมัติ ให้กำหนดคูปอง/โปรโมชั่นจริงจากระบบโปรโมชั่นเดิมและระบุเงื่อนไขในข้อความ

## ศูนย์ข้อความ

- `/Messages` สมาชิกเริ่มติดต่อทีมงานได้ ส่วน CustomerService/Admin/SuperAdmin เริ่มติดต่อสมาชิกหรือตอบได้
- แสดงสถานะรอเจ้าหน้าที่ รอสมาชิก และปิดเรื่อง พร้อมเวลาส่ง/อ่าน
- ข้อความแจ้งเตือนในแอปและตัวเลขยังไม่อ่านบนเมนูรีเฟรชทุก 30 วินาที เปิดเรื่องเพื่ออ่านข้อความและส่งการยืนยันอ่านผ่าน POST ที่ตรวจ CSRF
- สมาชิกไม่สามารถอ่านหรือตอบเรื่องของสมาชิกคนอื่น การส่งซ้ำด้วย request key เดิมไม่เพิ่มข้อความซ้ำ
- ปิดเรื่องพร้อมเหตุผลและ audit ได้ ถ้าต้องการคุยต่อให้เปิดเรื่องใหม่ ไม่มีการส่งแคมเปญจริงให้สมาชิกโดยอัตโนมัติ

## รายงานและหน้าต่างพิมพ์

- ปุ่มพิมพ์บนรายงานสต๊อก หลังบ้าน สมาชิก ใบเบิก ใบเสร็จ และบัญชี เปิดตัวอย่างใน modal ก่อน
- ตัวอย่างเป็นข้อมูลหน้าปัจจุบันและตัวกรองปัจจุบัน ไม่รวมทุกหน้าของรายงานที่แบ่งหน้า
- ปุ่มเปิดหน้าต่างพิมพ์เปิดหน้าต่างแยก แล้วกดพิมพ์หรือบันทึก PDF ผ่านเบราว์เซอร์
- ไม่รวมฟอร์มแก้ไข ปุ่ม และเมนูในรายงานพิมพ์

## บัญชีย่อยการขาย

- `/Accounting` ใช้สิทธิ์ Finance/Admin/SuperAdmin มีตัวกรองวันที่ไทย สรุปตามบัญชี และสมุดรายวัน
- สร้างรายการภายใน transaction เดียวกับการยืนยันชำระเงิน/ขาย POS และอนุมัติคืนสินค้า เริ่มจากธุรกรรมใหม่หลังติดตั้งโมดูล ไม่สร้างรายการย้อนหลังให้รายการเก่าโดยไม่ตรวจสอบ
- ทุกเอกสารเดบิตต้องเท่ากับเครดิต ใช้ event key ป้องกันบันทึกซ้ำ ห้ามแก้ไข/ลบรายการที่ลงบัญชีผ่าน EF และ SQL triggers
- ผังบัญชีเพื่อการบริหาร: 1010 เงินสด, 1020 ธนาคาร/ช่องทางรับเงิน, 1030 สินค้าคงเหลือ, 2010 ภาษีตามคำสั่งซื้อ, 4010 รายได้สินค้า, 4020 รายได้ส่งสินค้า, 4090 ส่วนลดจาก Token, 5010 ต้นทุนขาย
- ตัวอย่างขายเงินสด 990 ต้นทุน 100: เดบิตเงินสด 990 เครดิตรายได้ 990; เดบิตต้นทุนขาย 100 เครดิตสินค้าคงเหลือ 100
- คืนเงินจะย้อนรายได้ ภาษี ค่าส่ง และส่วนลดตามยอดคืนจริง ส่วนต้นทุนจะคืนเฉพาะส่วนที่ระบบคลังรับกลับเป็นสต๊อกขายได้
- นี่เป็นบัญชีย่อยสำหรับตรวจการขาย ไม่ใช่ระบบบัญชีทั่วไปครบชุด ไม่รวมยอดยกมา จัดซื้อ เจ้าหนี้ ภาระรางวัล Token ค่าธรรมเนียมค้างจ่าย การปิดงวด หรือการรับรองงบการเงิน
- ค่าภาษีใช้ยอดจากคำสั่งซื้อเดิม โมดูลนี้ไม่ได้กำหนดอัตราภาษีหรือออกใบกำกับภาษีใหม่
