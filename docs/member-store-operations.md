# ร้านค้าสมาชิกและ Token เครือข่าย

## การใช้งาน

1. สมัครที่ `/Account/Register` ยืนยันอีเมล แล้ว Login ที่ `/Identity/Account/Login` ระบบเดิมสร้างคลังสมาชิกและ POS ให้
2. ไป `/MyStore` กดสร้างร้านแบบร่าง กรอกชื่อ รายละเอียด เบอร์ติดต่อ แล้วบันทึกการเปิดร้าน
3. ที่ `/MyStore/Products` เปิดสินค้าที่ต้องการขาย ใช้ราคาปลีกกลาง ลิงก์ร้านคือ `/s/{รหัสสมาชิกตัวพิมพ์เล็ก}` ดาวน์โหลด QR ได้จากหน้าร้านของฉัน
4. เติมสินค้าด้วย `/Transfers` และยืนยันรับจริง ติดตามคลังกับ stock card ที่ `/MyStore/Inventory` สต็อกออนไลน์ใช้คลังสมาชิกเดียวกันกับ POS เมื่อ POS ผูกคลังนั้น
5. ลูกค้าเลือกสินค้าและตะกร้าภายในร้าน สินค้าจองเมื่อยืนยัน checkout ร้านแต่ละร้านและร้านกลางมีตะกร้าแยกกันบนเบราว์เซอร์
6. รับเงินผ่านคำแนะนำการโอนเดิม ฝ่ายการเงินตรวจรับเงิน หลังชำระเจ้าของร้านจัดส่งและบันทึกเลขพัสดุที่ `/MyStore/Orders` การยกเลิก/ขอคืนใช้หน้ารายละเอียดออเดอร์ ฝ่ายการเงินยังเป็นผู้อนุมัติคืนเงินและยืนยันขายปลีกเพื่อสร้างรางวัล
7. `/MyStore/Accounting` แสดงสมุดย่อยขาย/คืนเฉพาะออเดอร์ร้านและ POS ของตน บันทึกค่าใช้จ่าย ส่งออก CSV และพิมพ์ได้ ค่าใช้จ่ายแก้ด้วยรายการกลับรายการ มีเหตุผลและป้องกันทำซ้ำ
8. `/NetworkTokens` แสดงกระเป๋าของตน รางวัลขายเอง/Loyalty และรางวัลอัพไลน์ L1–L3 จากยอดขายดาวน์ไลน์ พร้อมยอดปรับคืน วันปลดล็อก หมดอายุ ประวัติ Token และรายชื่อเครือข่ายปัจจุบัน

## กติกาที่ใช้ในรุ่นนี้

- หนึ่งสมาชิกมีหนึ่งร้าน ใช้คลังของสมาชิก เจ้าของจัดส่งเอง ราคาและการตรวจรับเงินเป็นระบบกลาง
- ร้านสมาชิกขายราคาปลีก ไม่ใช้คูปองร้านกลาง เครดิตบริษัท หรือรายการซื้อเติมสต็อกผ่านร้านสมาชิก รายการเหล่านั้นยังทำที่ร้านกลางได้
- Token ใช้ส่วนลดซื้อสินค้าตามกติกาเดิม ไม่มีการโอนระหว่างอัพไลน์และดาวน์ไลน์ตามคำยืนยันผู้ใช้
- ยอดรางวัลของคนอื่นและข้อมูลลูกค้าของร้านอื่นไม่เปิดให้สมาชิกดู ลำดับเครือข่ายของรางวัลคง snapshot เดิมแม้เปลี่ยนผู้แนะนำภายหลัง
- ต้นทุนในบัญชีร้านใช้ต้นทุนล็อตในระบบ ส่วนต่างที่แสดงหักต้นทุน ส่วนลด Token และค่าใช้จ่ายที่ลงไว้ ไม่ใช่การรับรองกำไรสุทธิทางบัญชี
- ยอดรับเงินผ่านบริษัทในสมุดย่อยไม่ใช่การยืนยันว่าบริษัทโอนเงินให้ร้านแล้ว ยังไม่มีระบบ settlement โอนจ่ายอัตโนมัติหรือบัญชีรับเงินเฉพาะร้าน
- ยังใช้การรับโอนคลังครบจำนวนต่อเอกสารตามระบบเดิม ไม่เพิ่มพนักงานร้าน ตรวจนับอนุมัติผลต่าง หรือรับโอนบางส่วนในรุ่นนี้ รายการเหล่านี้เป็นส่วนขยายในเอกสารออกแบบ

## อัปเดตฐานข้อมูลและ IIS

ต้องใช้ migration `MemberStores` ก่อนรันรุ่นใหม่ เพิ่มตาราง MemberStores, StoreProducts, StoreExpenses และคอลัมน์ StoreId/StoreName โดยไม่เปลี่ยนความหมายออเดอร์เก่า ร้านและตะกร้าเก่าไม่มี StoreId จึงยังเป็นระบบเดิม

```powershell
dotnet run --project src/AmHerb.Web --no-build --launch-profile http -- --migrate
dotnet publish src/AmHerb.Web -c Release -r win-x64 --self-contained false -o artifacts/publish-member-store
```

สำหรับ IIS ใช้ .NET 8 Hosting Bundle / App Pool 64-bit ตั้งค่าฐานข้อมูลและบัญชีรับเงินตามคู่มือ `iis.md` สำรองฐานข้อมูลก่อน migration และนำเว็บออกจากบริการชั่วคราวระหว่างเปลี่ยนไฟล์ ฐาน demo ที่มี baseline จะขยายโครงสร้าง baseline ให้ตรงกับตารางใหม่โดยไม่เปลี่ยนข้อมูลธุรกิจเดิม

## การตรวจรับ

ชุด `MemberStoreTests` ตรวจเจ้าของร้าน ตะกร้าแยกร้าน สต็อก/replay/ยกเลิก ค่าใช้จ่ายแก้ย้อนหลังไม่ได้ และสิทธิ์ดู Token ชุด `MemberStoreBrowserTests` ทดสอบ guest checkout, owner management, shipping, accounting, network, ปฏิเสธเจ้าของร้านอื่น และหน้าจอมือถือ โดยใช้ฐาน `AmHerb_Test_{guid}` แยกและลบหลังทดสอบ

```powershell
$env:AMHERB_RUN_SQL_TESTS = '1'
$env:AMHERB_RUN_BROWSER_TESTS = '1'
dotnet test tests/AmHerb.Tests
```
